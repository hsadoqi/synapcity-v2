# @synapcity/frontend-forms

Owns: the form interaction foundations ([ADR-0015](../../../docs/architecture/decisions/0015-forms-package-and-form-state.md)) and, in this package, the schema-driven form engine from the [engine plan](../../../docs/superpowers/plans/2026-10-24-forms-schema-driven-engine.md). The caller passes a Zod object schema, normally from `domain`, and describes how each key is presented and when it applies; the package checks that description, works out which fields are visible, enabled and required for the current values, and (in later tasks) builds the validation schema, renders the form and shows its errors. The package owns no product schema, copy or workflow.

Runtime: browser and server rendering, framework-neutral. Dependencies: `@synapcity/frontend-ui` (the input, label and password input that `FormField` composes), `react` and `zod`. `react-hook-form` and `@hookform/resolvers` (used by `useActionForm`; only this package imports them, and no other workspace can resolve them). `useFocusFirstError` is a client hook (`'use client'`); the rest renders on the server or in the browser. Category rules: [frontend README](../README.md) and [ADR-0014](../../../docs/architecture/decisions/0014-multi-app-package-boundaries.md).

History: created by Task 1 of the engine plan, ahead of extraction Part A, with the engine's pure modules as its first code (decision D16 in the plan, awaiting the owner's confirmation). Extraction Part A then moved the form pieces out of `apps/web` unchanged (2026-10-24): `FormField`, `FormMessage`, `fieldErrorProps` and `useFocusFirstError`, with their tests. No message, ARIA wiring, focus behavior or redirect changed. `FormField` is not absorbed by `frontend-ui`'s `field` component yet; that is a later change, after the engine's field frame exists.

| Export                                              | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FormField`                                         | A label, an input (a password input with its reveal control for passwords), an optional hint, and the `aria-invalid` and `aria-describedby` wiring to its form's message. The hint steps aside while the field is invalid.                                                                                                                                                                                                                                                    |
| `FormMessage`, `FormMessageState`                   | The form's error (an alert that can take focus) or status line, with an id the form supplies so two forms on one page never share one.                                                                                                                                                                                                                                                                                                                                        |

| `useFocusFirstError`                                | After a failed submit, focuses the first marked field that is empty, else the first marked field, else the form's own message, looking only inside its own form.                                                                                                                                                                                                                                                                                                              |
| `useActionForm`                                     | Client-side validation for a form that still submits to a server action. The form keeps its `action` and works before hydration; once hydrated, the submit handler validates the form's data against the same schema the action uses, shows a refusal at once in the server's `{ error, fields }` shape, and otherwise calls the action unchanged. Files pass through, and a name that appears more than once becomes a list. Used by the forgot-password and register forms. |
| `defineForm`, `FormDefinitionError`                 | Checks a definition when it is written and throws one error listing every problem. Call it at module scope so a broken definition fails in a test or build, never while rendering.                                                                                                                                                                                                                                                                                            |
| `describeSchemaField`                               | Describes one key of an object schema: its kind, whether it accepts `undefined` or `null`, an email format, enum values.                                                                                                                                                                                                                                                                                                                                                      |
| `resolveFieldStates`, `isEmptyValue`                | Works out whether each field is visible, enabled and required for the current values, in dependency order; a hidden field reads as empty to its dependents. `0` and `false` are values, never empty.                                                                                                                                                                                                                                                                          |
| `buildSchema`, `createSchemaBuilder`                | The caller's schema narrowed to the visible fields, with `require` dependencies and cross-field rules applied. The builder caches by which fields are visible and required.                                                                                                                                                                                                                                                                                                   |

There is no fallback renderer; an unknown type throws an error that names the type.                                                                                                                                                                                                                                                                                        |

The registry is copied once on mount; `extend` adds a feature's `custom:*` renderers for that provider only.                                                                                                                                                                                                                                                                                                                    |

## Rules

- Kind folders directly under `src/`, one folder per unit with its tests and an `index.ts`; imports between folders go through the folder's `index.ts`.
- `types/` and the pure `utils/` units import neither React nor React Hook Form, so they can move to a domain package if a server consumer appears.
- A field carries no schema: the caller's schema owns validation. `defineForm` rejects a schema with object-level refinements, because Zod 4.6.7 cannot narrow one; cross-field checks are passed as `rules`.
- Field names must be schema keys and must not be `type`, `root`, `ref`, `types`, `message` or `form`, which collide with React Hook Form's internal error shapes.
- The narrowed schema is built from `schema.shape`, never `.pick()`, which throws on a refined schema in Zod 4.6.7. A field required by a `require` dependency starts from `unknown`, because Zod does not validate an optional key that is absent from the input.
- A key that is nullable but not optional fails when it is absent, so the form must start it as `null`. A cross-field rule runs alongside ordinary field issues, but Zod skips it when a type error exists elsewhere in the object.
- Render a component that comes from the registry with `createElement(registry.resolve(type), props)`; JSX on a resolved component trips the `react-hooks/static-components` lint rule.
- `useActionForm` keeps the `<form>`'s `action` and `noValidate`, validates the form's own `FormData`, and never calls React Hook Form's `reset()` (it also resets the DOM form and would wipe what was typed). React 19 resets a form after its action finishes and React Hook Form does not see that, so values are synced from the form's data just before validating.
- Errors and messages name fields and types, never values.
