# Design Tokens

Design tokens are the contract between the theme engine, `globals.css`, and the UI.

Synapcity separates persisted inputs, generated palette variables, semantic aliases, and future layout tokens.

---

## Persisted Theme Inputs

V0 persists canonical theme inputs:

```ts
type ThemeRecord = {
  id: string
  name: string
  primaryOklch: string
  accentOklch: string
  mode?: 'light' | 'dark' | 'system'
  version: number
}
```

These values are the source of truth.

---

## Runtime Generated Palette Tokens

Generated by the runtime engine from persisted OKLCH seeds:

```text
--primary-50 ... --primary-950
--accent-50 ... --accent-950
```

The runtime engine should not generate semantic token values.

---

## Semantic Tokens

Consumed by components and mapped in `globals.css`:

```text
--background
--foreground
--surface
--surface-muted
--card
--card-foreground
--popover
--popover-foreground
--primary
--primary-foreground
--accent
--accent-foreground
--muted
--muted-foreground
--border
--input
--ring
--success
--warning
--danger
--info
```

Example mapping:

```css
--background: var(--primary-50);
--foreground: var(--primary-900);
```

## Rule

Persist theme records and assignments. Generate palette scales at runtime. Let `globals.css` define semantic aliases. Components consume semantic tokens.
