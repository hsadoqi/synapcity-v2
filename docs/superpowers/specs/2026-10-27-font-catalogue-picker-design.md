# Font Catalogue Picker

**Status:** Approved (owner, 2026-10-27), decisions D1 to D4 as recommended. Reviewed 2026-10-27 (section 8): D1 to D4 stand; sections 3.1 to 3.6 and 4 are corrected, and the changes that need the owner's word are listed as O1 to O4.  
**Date:** 2026-10-27  
**Requested by:** Repository owner  
**Scope:** Let a person choose any suitable Google Fonts family for the heading, body and code roles through a searchable combobox, replacing the 19 hand-picked families. Changes a persisted preference value; the shipped default typefaces are out of scope.

## 1. Current behaviour

- `packages/domain/preferences/src/schemas/fonts/fonts.ts` lists 19 families by id (`googleFonts`) and three per-role lists (`headingFonts`, `bodyFonts`, `codeFonts`), each starting with `'default'`.
- `theme.ts` and `look.ts` validate `headingFont`, `bodyFont` and `codeFont` with `z.enum(...)` over those lists, so an unknown id is rejected, including in exported files. In `lookSchema` one bad field rejects the whole look. The file's rule: ids are never removed or renamed.
- The three fields are **account-owned** (`utils/scope/scope.ts`), so they are also stored in Supabase, in `user_preferences.preferences` (`jsonb`), and travel in export files (`TRANSFER_FILE_VERSION` 2).
- `frontend-preferences` `font-loading.ts` builds a Google Fonts stylesheet URL and a CSS stack from an id; `font-preferences.ts` adds the stylesheet when a family is chosen and writes `--font-preference-heading`, `--font-preference-body` or `--font-preference-code`.
- `lookHtmlAttributes` (`utils/look-html`) runs on the server in both root layouts and calls `fontStack` for every chosen font, so the font helpers are on every server render.
- `look-source.ts` builds `lookCookieExpression`, which inlines every allowed id per field. That expression is inlined into **every** boot script (appearance, font, theme shape), and `fontBootScript` also inlines a 19-entry table of stylesheet URLs and stacks. `boot-scripts.expected.json` pins the generated scripts.
- `features-settings` `font-rows.tsx` renders a `SettingsSelect` per role with a `FontPreview` under it.
- `@synapcity/frontend-ui` already has a Base UI combobox with groups and a `ComboboxVirtualList` (`useVirtualList`).

## 3. Design

### 3.1 Catalogue (`domain-preferences`)

- A generator script requests `https://www.googleapis.com/webfonts/v1/webfonts?sort=popularity&key=…` and writes a trimmed JSON with, per family: `family`, `category`, and `popular` (true for the first 30 by popularity; O3). No weights: section 3.4 builds the stylesheet URL without them. _Superseded: "available weights, popularity rank". A full rank changes on almost every regeneration and makes the diff unreadable._
- The generator keeps only families that can be used as written:
  - the family has a `regular` variant. Google's CSS API answers 400 for a family with no weight 400 even with no weight requested (checked 2026-10-27: `Buda`, which has only 300);
  - its `subsets` include `latin` (the interface is written in Latin script);
  - it is not on a short denylist of families that are not text: `Libre Barcode*`, `Flow *`, `Redacted*`, `Noto Color Emoji`, and any the first run turns up.
- It also checks, and fails without writing, if: a family does not match the shape rule of section 3.3; a family equals `default` in any case; two families give the same slug; a legacy family from `googleFonts` is missing.
- Output is sorted by family with stable key order, so a regeneration diff shows only real changes. The key is never printed, including in error messages and the request URL.
- Typed readers in a separate entry point that only settings code, import and the server import: `fontCatalogue`, `isCatalogueFamily(family)`, `familiesForRole(role)`, `fontCategory(family)`.
- `googleFonts` becomes the legacy map from id to family, kept for reading old values.

### 3.2 Persisted value: two levels of checking

The schemas are used in browser code that must not carry the snapshot (the shared look store, the look cookie, the settings provider on every page that mounts it), so the check is split:

- **Shape (in `themeSchema` and `lookSchema`, everywhere, no snapshot):** accepts `'default'`, a legacy id (turned into its family on parse), or a string matching the shape rule (section 3.3). Anything else is rejected exactly as today, the look as one unit.
- **Catalogue (settings picker, settings import, the Server Action that saves account preferences):** a new choice must be a catalogue family allowed for its role. The server repeats this on write, so a tampered request cannot store an unlisted value.
- A well-formed saved family that is not in the current snapshot keeps applying; the settings row shows it with "no longer in the list" and the person can keep or replace it. If Google no longer serves it, the request fails and the role shows its shipped font (section 3.4).
- _Superseded: "A saved family that is no longer in the snapshot reads as `'default'`". It contradicted "an unknown family is rejected" (the schema cannot tell the two apart), lost the value the settings row was meant to describe, and needed the snapshot in every schema user._
- **No `LOOK_VERSION` change.** The new shape accepts every value the old one did, so old cookies, stored documents, database rows and export files parse without a migration. _Superseded: "`LOOK_VERSION` increases, with a migration from the previous version". `lookSchema` uses `z.literal(LOOK_VERSION)` and every boot script checks `c.v!==1`, so a bump would reject every existing cookie and stored look at first paint until each was rewritten, and an older build still rejects the new value whatever the number is._
- Database rows and export files with legacy ids are not rewritten; they are read as families and saved as families the next time they change.

### 3.3 Head script

- Inlining about 1,900 families into every page is too large. The scripts check the value's shape and build what they need from the family name alone (section 3.4), so no catalogue data is inlined.
- Shape rule: `'default'`, one of the 19 legacy ids, or `^[A-Za-z0-9][A-Za-z0-9 ]{0,63}$`. It admits no quote, backslash, semicolon, parenthesis or URL character, so a tampered cookie or `localStorage` value cannot inject CSS or change the stylesheet host. The same rule, from one constant, is used by the schema, by `lookCookieExpression` and by the `localStorage` branch of `fontBootScript`. The generator (3.1) proves every catalogue family passes it.
- The 19-entry legacy map (id to family) is inlined once, in `fontBootScript`. The cookie expression inlined into the other boot scripts gets the shape rule and the 19 ids, nothing more.
- Size bound: each generated boot script is no longer than today's version in `boot-scripts.expected.json`. `fontBootScript` should shrink, since its 19 URLs and stacks go.
- Full catalogue validation happens only where 3.2 says. _Superseded: "Full validation runs in the schema after hydration and resets a value that fails." That reset would make the settings row's "no longer in the list" impossible and put the snapshot in the browser bundle._

### 3.4 Loading

- `fontStylesheetUrl(family)`: `https://fonts.googleapis.com/css2?family=<family, spaces as +>:wght@400;500;600;700&display=swap`. A list of discrete weights works for every family that has weight 400: the API returns the weights the family has and leaves out the rest (checked 2026-10-27: `Lobster` returns 400 only, `Lora` and `Fira Code` return all four). A weight range such as `400..700`, which the current helpers send, fails with 400 on a family that has no variable weight axis (checked: `Lobster`), so ranges are not used. _Superseded: "Weights … come from the catalogue". With the fixed list, the browser code needs no catalogue._
- `fontStack(family, role)`: `'<family>', <the role's shipped default>`, for example `'Lora', var(--font-inter, system-ui)` for body and `'Fira Code', var(--font-geist-mono, ui-monospace)` for code. A slow, blocked or failed request shows the app's own font for that role, the same on the server, in the boot script and in the settings provider, with no catalogue (O2). _Superseded: "the generic fallback come[s] from the catalogue (`display` and `handwriting` fall back to … `sans-serif` unless the catalogue says `serif`)"._
- Link element ids: `font-preference-<slug>`, the slug from one shared function that the boot script is generated from. Preview links (section 3.5) use `font-preview-<slug>`, so a preview never counts as the loaded font.
- Behaviour otherwise unchanged: stylesheets load only when a family is chosen, start as `media=print` and switch on load, and record `data-status`.
- Italics are not requested, as today (enhancement E3).

### 3.5 Picker (`features-settings`)

- The installed `@synapcity/frontend-ui` combobox with `ComboboxVirtualList` replaces `SettingsSelect` in `font-rows.tsx`. Virtualisation from the start: the longest role list (heading) is well over a thousand families. _Superseded: "Virtualise the list if the combobox does not handle the longest role list smoothly."_
- With an empty query: the Popular group, then A to Z **without** the Popular families, so no family appears twice (two options with one value would both show as selected and give screen readers two matches). With a query: one flat list, prefix matches first, then other matches, each by popularity; case and accents ignored.
- `'default'` ("Default (Geist)" and the like) is the first option in every state.
- Each option's accessible name is the family name, in the interface font. A short sample in the family itself sits beside it, `aria-hidden`, so a decorative family never makes an option unreadable.
- A sample loads its family through a preview link with the `text=` parameter (only the glyphs of the sample; checked 2026-10-27 that the API accepts it) and only after the option has been visible for about 150 ms, so scrolling fast does not start hundreds of requests.
- `FontPreview` takes the family.
- Keyboard, focus and screen reader behaviour come from the combobox; the row's label stays connected to the input.

### 3.6 Default labels

- "Default (Geist)" and the like stay in `domain-preferences` (`defaultFontLabels`). `domain` may not import `frontend` (ADR-0014 matrix), so they cannot come from the shared default fonts package. _Superseded: "come from the shared default fonts package once it exists". This removes the only dependency between the two plans._

## 4. Risks

- **Privacy:** chosen fonts already load from `fonts.googleapis.com` and `fonts.gstatic.com`; no new destination. Previews in the picker send more requests there while somebody browses (O4).
- **Readability:** role filters reduce poor choices without removing them; the preview stays directly under the picker; non-text families are left out of the snapshot.
- **Snapshot drift:** a saved family missing from a newer snapshot keeps working and is labelled (3.2).
- **Bundle size:** the snapshot is imported only by the catalogue entry point (3.1): settings code, import and the server. Never by the schemas, the boot scripts, `lookHtmlAttributes` or the shells. Measured in the build. _Superseded: "imported by settings code only". As first designed, the schemas and the loading helpers would have pulled it into every page._
- **Deploy skew:** `apps/web` and `apps/docs` read the same look cookie and the same account row. A host on an older build rejects a look holding a family name and falls back as a unit. Deploy both from the same commit.
- **Exports:** files exported after this change hold family names; an older build cannot import them. Files exported before it import into the new build.
- **Google's response:** checked on 2026-10-27 from one network with one browser user agent. Task 4 tests pin the URL format, and the e2e tests stub Google so they do not depend on it.

## 5. ADR change

Amend ADR-0003: the curated list becomes the catalogue snapshot with role filters; the persisted value becomes the family name with legacy ids accepted; rewrite item 5 (adding a selectable font now means regenerating the snapshot, not adding a loader) and the matching half of `AGENTS.md` line 139.

### 5.1 Enhancements, not adopted

Proposed in the 2026-10-27 review and not yet decided. Section 3.4 refers to E3. _Recorded here on 2026-10-27; until then the list existed only in that review's conversation._

- **E1. Load chosen fonts with the page.** Both layouts already read the saved look on the server, so the server can put the font's stylesheet link in the page head, and the download starts with the HTML instead of waiting for the boot script. Cost: the link is built in two places, with a test that they agree.
- **E2. Flag a stale snapshot.** A no-network test warns when the saved catalogue is more than six months old.
- **E3. Request italics.** Today italics are synthesised by the browser. How Google answers for families without an italic was not checked, so a live check comes first.
- **E4. One request for all chosen fonts.** It saves up to two requests, but makes de-duplicating loaded families harder.

## 6. Out of scope

Shipped default typefaces, uploaded font files, sources other than Google Fonts, per-space or per-document fonts.

## 7. Open questions for the owner

- **O1.** The two-level check in 3.2 (shape everywhere, catalogue where the snapshot is allowed) and keeping an unlisted saved family instead of resetting it.
- **O2.** The fallback in 3.4 is the role's shipped font rather than a generic family. A serif choice that fails to load shows Inter or Geist, not the browser's serif.
- **O3.** How many families count as Popular (30 proposed).
- **O4.** Whether previews and chosen fonts should wait for consent the way error reports do. Not part of the approved design; listed because previews increase requests to Google.

## 8. Review, 2026-10-27

**Verified by reading the files on `feat-tokens-package`:** the schemas, `lookSchema`'s `z.literal` version and one-unit rejection, the account scope of the font fields and the `user_preferences` migration, `lookHtmlAttributes`, the boot scripts and `boot-scripts.expected.json`, `font-loading.ts`, `font-rows.tsx`, the combobox's virtual list, the ADR-0014 matrix.
