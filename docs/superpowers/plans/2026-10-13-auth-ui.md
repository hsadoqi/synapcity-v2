# Auth UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show signed-in or signed-out state in the header and root page, with an avatar user menu and a single sign-out component.

**Architecture:** `RootHeader` in `packages/frontend/ui` gets an `actions` slot. Presentational `UserMenu` and `AuthButtons` live in the UI package. `apps/web` resolves the session on the server (`getClaims()`) in an `AuthActions` server component and fills the slot. Sign-out is one `<form action={signOut}>` component.

**Tech Stack:** Next.js 16 App Router, React 19, Base UI via shadcn `base-mira`, Tailwind v4 tokens, Supabase SSR, Vitest, Storybook 10.

**Spec:** `docs/superpowers/specs/2026-10-13-auth-ui-design.md`

## Global Constraints

- UI only. No changes to Supabase config, schema, `route-access.ts`, `app/auth/actions.ts`, or any `package.json` dependency.
- No hardcoded colours, no `dark:` colours, no bracket values, no `style={{}}`, no `!important` in code you write.
- `className` on shadcn components is for layout only; use variants for the rest. Merge classes with `cn()` (import `cn` from `'cn'` inside the UI package, `@/lib/utils` in `apps/web`).
- Icons from `lucide-react` only.
- `packages/frontend/ui` must not import Supabase or anything from `apps/web`.
- `Button` sets `aria-label` from its `label` prop and defaults it to `"button"`, so always pass `label` on a `Button` whose visible text differs or is an icon/avatar.
- Commit only if the human has authorized commits for this work. End commit messages with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Never write a GitHub closing keyword near an issue reference.
- Verify with the repo scripts only (`pnpm format:check`, `lint`, `typecheck`, `deps`, `test`, `test:storybook`, `build`). Report exactly what ran and what did not.

## Review Focus

- Name missing from user metadata: the menu and avatar must fall back to the email, and initials to `?` only if both are absent. Pinned in Task 1 and Task 4.
- Email missing (e.g. phone or anonymous user): the menu label must not render `undefined` or an empty line. Pinned in Task 4 (`profileFromClaims`) and Task 1 (`UserMenu`).
- Avatar image fails to load: the fallback initials must show (Base UI `AvatarFallback`). Covered by the `BrokenImage` story in Task 1.
- Sign-out pending: the button must disable and not double-submit. Pinned in Task 4.
- Open redirect surface: no new `next` handling is added. Hero and header links use fixed paths, and the signed-in link uses `DEFAULT_NEXT_PATH`.

```ts
// packages/frontend/ui/src/utils/initials.ts
export function initialsOf(name: string | null | undefined): string {
  const letters = (name ?? '')
    .split(/\s+/)
    .filter(Boolean)
    .slice(0, 2)
    .map((word) => word[0])
    .join('')
    .toUpperCase();
  return letters || '?';
}
```

```tsx
// packages/frontend/ui/src/components/user-menu.tsx
'use client';

import type { ReactNode } from 'react';

import { initialsOf } from '../utils/initials';
import { Avatar, AvatarFallback, AvatarImage } from './ui/avatar';
import { Button } from './ui/button';
import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuGroup,
  DropdownMenuLabel,
  DropdownMenuSeparator,
  DropdownMenuTrigger,
} from './ui/dropdown-menu';

type UserMenuProps = {
  name: string | null;
  email: string | null;
  imageUrl: string | null;
  children?: ReactNode;
};

function UserMenu({ name, email, imageUrl, children }: UserMenuProps) {
  const displayName = name ?? email;

  return (
    <DropdownMenu>
      <DropdownMenuTrigger
        render={
          <Button
            data-slot="user-menu-trigger"
            variant="ghost"
            size="icon-xl"
            label="Account menu"
          />
        }
      >
        <Avatar>
          {imageUrl && <AvatarImage src={imageUrl} alt="" />}
          <AvatarFallback>{initialsOf(displayName)}</AvatarFallback>
        </Avatar>
      </DropdownMenuTrigger>
      <DropdownMenuContent align="end">
        <DropdownMenuGroup>
          <DropdownMenuLabel className="flex flex-col gap-0.5">
            {name && <span className="text-foreground">{name}</span>}
            {email && <span>{email}</span>}
          </DropdownMenuLabel>
        </DropdownMenuGroup>
        {children && <DropdownMenuSeparator />}
        {children}
      </DropdownMenuContent>
    </DropdownMenu>
  );
}

export { UserMenu };
export type { UserMenuProps };
```

Note: the avatar image uses `alt=""` because the trigger already carries the accessible name.

- [ ] **Step 3: Implement the mapper**

`user_metadata` is user-editable; this is display data only, never an authorization input.

```ts
// apps/web/src/lib/auth/profile.ts
export type DisplayProfile = {
  name: string | null;
  email: string | null;
  imageUrl: string | null;
};

type ClaimsLike = {
  email?: unknown;
  user_metadata?: Record<string, unknown> | null;
};

function text(value: unknown): string | null {
  return typeof value === 'string' && value.trim() ? value : null;
}

/** Display-only. `user_metadata` is user-editable: never authorize with it. */
export function profileFromClaims(claims: ClaimsLike): DisplayProfile {
  const meta = claims.user_metadata ?? {};
  return {
    name: text(meta.full_name) ?? text(meta.name),
    email: text(claims.email),
    imageUrl: text(meta.avatar_url),
  };
}
```

- [ ] **Step 6: Implement `AuthActions`**

```tsx
// apps/web/src/components/auth/auth-status.tsx
import { AuthButtons } from '@synapcity/frontend-ui/components/auth-buttons';
import { LinkButton } from '@synapcity/frontend-ui/components/link-button';
import { UserMenu } from '@synapcity/frontend-ui/components/user-menu';

import { DEFAULT_NEXT_PATH } from '@/lib/auth/safe-next';
import { profileFromClaims } from '@/lib/auth/profile';
import { createClient } from '@/lib/supabase/server';

import { SignOutButton } from './sign-out-button';

/**
 * Reads the verified session claims on the server (ADR-0006) so the first paint
 * already matches the signed-in state. Claims are for display only.
 */
export async function AuthActions({
  variant = 'header',
}: {
  variant?: 'header' | 'hero';
}) {
  const supabase = await createClient();
  const { data } = await supabase.auth.getClaims();

  if (!data?.claims) return <AuthButtons variant={variant} />;

  if (variant === 'hero') {
    return (
      <LinkButton href={DEFAULT_NEXT_PATH} variant="default" size="lg">
        Go to your workspace
      </LinkButton>
    );
  }

  const { name, email, imageUrl } = profileFromClaims(data.claims);
```
