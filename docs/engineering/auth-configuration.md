# Auth configuration: local and hosted

**Status:** Current direction. What the local stack's Auth settings are, what the hosted project's are known to be, and where they differ (owner decision D11: local mirrors the hosted security semantics).

The local values are in `supabase/config.toml`. The hosted values are not read by any tool in this repository; where the repository documents a hosted setting the source is named, and where it does not, the cell says **not verified**. Closing a "not verified" cell needs the owner or an operator to run the read-only `supabase config diff` against the hosted project, behind the deployment gates; an agent does not.

## One local origin

Auth flows run on `http://127.0.0.1:3000` (`pnpm dev:web:local`): it is the stack's `site_url` and its redirect entry, so every emailed link returns to it. The `.env.example` `SITE_URL` is that origin. `pnpm dev` (port 8080) is for development fixture mode, which has no session.

## Confirming a sign-up locally

With confirmations on, a sign-up sends a mail to the local Mailpit inbox (`http://127.0.0.1:54324`); open the link in it. Accounts created through the Admin API (the end-to-end tests) are created confirmed and are unaffected.

## Open items for the owner

1. **Manual linking.** Owner decision D11 and the S6a specification say manual identity linking stays off until a feature uses it. Settings already has "Linked accounts" rows that call `linkIdentity`, and `apps/web/README.md` lists "Enable Manual Linking" as a setting those rows need. So a feature does use it. Locally it is off, so connecting or disconnecting Google or GitHub fails here; the hosted value is not verified. The owner should say whether D11 means "off until now" (turn it on, here and hosted, with a test for the rows) or "off, and the rows are not supported yet".
2. **Avatar upload cannot succeed locally.** `profiles.avatar_url` must start with `https://` (`profiles_avatar_url_https`), and the local stack's public Storage URL is `http://127.0.0.1:…`, so saving a photo fails with a check violation against it (and leaves the uploaded file behind until cleanup; the recoverable cleanup is slice S6b). Hosted URLs are https, so it works there. Loosening the constraint locally is a schema change and was not made; the signed-in tests therefore do not cover a photo.
3. **Hosted values.** The "not verified" rows above.
